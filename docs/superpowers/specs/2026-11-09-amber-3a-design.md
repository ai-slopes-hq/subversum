# Subversum: этап 3a, звук мира amber

Дата: 2026-11-09. Статус: на ревью автора. Родительская спека: `2026-11-09-rust-wasm-refactor-design.md` (этап 3 разрезан на 3a и 3b).

## 1. Цель и границы

3a переносит на Rust всё, что звучит и играет в мире amber: патч, мелодию, секвенсор, макросы, голос. Скин, ввод и приложение в `/next/` остаются на 3b.

Критерии успеха:
1. Для любого сида `roll()` и `makeSeq` дают тот же патч и те же 16 шагов, что legacy.
2. Нативный рендер проходит проверки из §6.
3. Автор послушал WAV и принял характер (субъективный критерий).
4. Минимальное подключение в `/next/` играет amber, чтобы послушать на телефоне. Скина нет, остаётся отладочный.

Вне объёма 3a: скин amber, жесты P-тап/hold/свайп на стороне ввода (в 3a только команды движка), шина эффектов (у amber её нет), другие миры, handoff между мирами (заглушка).

Решения автора (09.11):
- Сид даёт тот же патч и ту же мелодию, что legacy; порядок розыгрыша сохраняется.
- Ворота: вактрол-`Lpg` (из slow-tide, уже в `versum-dsp` v0.2.0).
- Фолд: табличный `Shaper` 4× из touch2decay с таблицей `sin(5π·x)`, не ADAA1.
- `blep`, `vco`, `lpg` перенёс автор (тег v0.2.0 поставлен). Остальное пишется в этом плане.
- Блоки живут в `versum-dsp` отдельным тегом v0.3.0; пока он не вышел, `engine` смотрит на локальный `[patch]`, в git он не коммитится.

Факты из исследования:
- В legacy у amber нет шины dub: голос идёт в мастер и лимитер (`index.html` 585–601, `applyMacros` для amber 1933–1944). «Lfo на 7 целей» из спеки — это LFO патча, не шины.
- В touch2decay нет amber, фолдера, LFO-блока, макросов и генератора мелодии. Есть `Biquad` (Q в дБ), `Rng`, `Osc.sine`, `StepClock`/`Steps`, `Shaper`, `DcBlock`, `Knee`. Остальное переписывается с JS legacy.
- `Vco` отдаёт 5 выходов (sine, tri, saw, pulse, sub), saw — индекс `SAW`.

## 2. Блоки `versum-dsp` v0.3.0

Контракт блока прежний (§4 родительской спеки): `new` аллоцирует, `process` без аллокаций, `reset`, NaN-guard, f32 звук и f64 фазы.

- `Biquad`: порт `core/sdk/biquad.hpp` из touch2decay. LP/HP, RBJ, Q в дБ как в Web Audio; `set` вызывается раз на блок, в `process` только шаг.
- `Shaper<N>`: порт `core/sdk/shaper.hpp`. Таблица-кривая на [−1, 1], линейная интерполяция, вход зажат до ±1, оверсэмплинг 4× по каскаду как у Chromium. Таблицу строит вызывающий код (`engine` строит `sin(5π·x)`).
- `Lfo`: синус и треугольник, частота в Гц, начальная фаза; шаг по блоку или по сэмплу.
- `StepClock`: порт `core/sdk/stepclock.hpp`, шаг — 16-я, точность до сэмпла, смена bpm без потери фазы.

У каждого блока свои тесты и участие в общей проверке (NaN, аллокации, DC). Вехи `Shaper`: сверка с эталоном Web Audio на сине и пиле по записи из legacy (допуск выберем по измерению).

## 3. Модули `engine`

```
crates/engine/src/
├─ patch.rs      Patch и roll(): порядок розыгрыша как в legacy
├─ melody.rs     makeSeq, makeStep, пул MIDI 24..47, 7 ладов
├─ macros.rs     Gesture → XM{dec, fm, fold, cut}
├─ amber.rs      мир: голос, LFO патча, P-тап
└─ (существующие) engine, protocol, peaks, probe
```

**`patch.rs`.** Поля как в legacy (`roll()` 611–634): oct, semi, wave (sine/tri/saw), fmRatio (выбор из FM_RATIOS, 25% шанс ±2%), fmIdx 0..4.5, fmSweep, depth 0.06..0.8, sym, sweep, decay (лог 0.12..1.8 с), attack 1..14 мс, cutoff (лог 900..9000), res 0..18 дБ, LFO (до двух), vis. Розыгрыш через `Rng` из `versum-dsp` (mulberry32, побитово как JS). Порядок вызовов `rng.next()` повторяет `roll()` строка в строку; порядок хранит тест-фикстура.

**`melody.rs`.** После `roll()` в том же потоке: bpm = round(rnd(110,135)), корень 0..11, лад из 7 `SCALES`, стартовый индекс, затем 16 вызовов `makeStep`: 22% пауза, иначе блуждание ±1..3 по пулу или прыжок (15%), скорость 1 с шансом 25%, иначе 0.62..0.85; шаг 0 всегда скорость 1. Пул — MIDI 24..47, отфильтрованный по ладу. Выход: массив из 16 шагов (ноль скорости — пауза).

**`macros.rs`.** Как legacy (`applyMacros` 1936–1942), XM читается на старте ноты:
- `dec = 2^(1.5·lpg)`, где lpg — ось X;
- `u = (color+1)/2`, `fm = 2u` при `u<0.5` иначе `1 + 0.5(2u−1)`;
- `fold`: сглаженная ступень (0.12..0.5) ниже середины, дальше `1 + 1.5(2u−1)`;
- `cut = 2^(0.8·color)`;
- Z (время удержания, `ZH` с задержкой 1 с и сглаживанием за 11 с) множит: dec на `2^(0.9ZH)`, fm на `1+0.35ZH`, cut на `2^(0.4ZH)`. Расчёт ZH ведёт движок по тактам аудио.

**`amber.rs`.** Моно-голос:
`Vco` (несущая по `wave` патча) с FM от синусного модулятора (второй `Vco` или `Osc`, индекс затухает с постоянной `tau·0.7` к `fmSweep`) → вход `Shaper` (`pre`-усиление = depth, затухает с `tau·0.9` к `sweep`, плюс DC `sym`) → `Biquad` HP 22 Гц Q 0.7 → `Lpg` (режим Combo, `decay`/`level` из патча и XM) → выход.
- Новая нота плавно гасит предыдущую за ~5 мс (два канала голоса, кроссфейд), без жёсткой обрезки.
- LFO патча: до двух `Lfo`, цели pitch (14 цент), ratio (120 цент), index, fold (0.18), sym, cut (1100 цент), res (3 дБ); частота 0.02..3 Гц (лог), форма sine/triangle, глубина 0.15..0.6. LFO общие на все ноты нажатия, фаза не сбрасывается между нотами.
- P-тап (`amberStab`): повтор последней ноты с velocity 1.2, attack 2 мс, cutoff ×3 (максимум 16 кГц), fmIdx ×1.4, decay ×1.3; заменяет звучащий голос.
- P-пинч (`pinch`) меняет FM ratio на старте ноты: отрицательный тянет к целому, положительный множит на `2^(0.55·d)`.
- Параметры патча отображаются на `LpgIn`/`LpgOpts`: отображение — отдельная задача на подгонку на слух.

**Мастер.** `Knee` + `DcBlock` из движка как сейчас; уровень калибруется под legacy-мастер 0.85 по рендеру.

**Секвенсор.** Шаг 0 играет сразу при старте. Дальше шаги по `StepClock`; `Hold` замораживает; смена `Tempo` без потери фазы. События шагов идут в телеметрию.

## 4. Протокол (телеметрия версии 2)

Команды:
- `Seed` теперь u32 в двух u16-полях (сейчас f32 теряет значения выше 2²⁴; исправляется в `crates/wasm` и `web/audio/protocol.ts`).
- `Gesture.pinch` начинает работать (сейчас всегда 0).
- Новая `PTap`.

Телеметрия (расширяет версию 1):
- `Patch`: bpm, корень, лад, цвет (оттенок, яркость, активность по `characterOf` legacy).
- `pattern[16]`: скорость на шаг, пауза — 0.
- `gate_env`: текущая огибающая ворот (читается скином вместо аналитической модели legacy).
- Версия в заголовке поднимается до 2; константная проверка раскладки в Rust и TS обновляется вместе.

Остальное прежнее: пакеты раз на кадр через `postMessage`, команды применяются в начале блока.

## 6. Тесты и приёмка

Нативно (`cargo test`):
- **Сверка с legacy.** Фикстура `legacy_seeds.json`: для нескольких сидов (включая ноль и значения выше 2²⁴) патч и 16 шагов, выгруженные из legacy. Тест сравнивает все поля и ноты; расхождение означает, что порядок розыгрыша нарушен.
- «Блоком = по сэмплу» побитово для блоков и мира; ноль аллокаций на `process`; нет NaN; DC после блока около нуля; пик ≤ 1; `alias_db` осциллятора и фолда не хуже −70 дБ.
- Тайминг секвенсора: границы шагов точны до сэмпла при bpm 110, 122, 135; `Hold` и смена `Tempo`.
- Макросы: контрольные значения XM для набора (lpg, color, ZH).
- Нативный рендер WAV 24 бит: несколько сидов и жесты X, Y, Z, P-тап.

Приёмка: все тесты зелёные, автор слушает WAV и принимает характер, затем слушает `/next/` на телефоне (запуск, мелодия, жесты).

## 7. Риски

- **Характер `Lpg`.** Вактрол звучит иначе, чем огибающая legacy; подгонка — отдельная задача с прослушиванием WAV, а не обещание тождества.
- **CPU.** `Shaper` 4× (~770 умножений на сэмпл) плюс два `Vco` в моно-голосе; замер на телефоне до 3b. Если дорого, разрешено упростить оверсэмплинг до 2× (решает автор).
- **Фикстуры.** Сверка зависит от того, что legacy выдаёт патч и шаги по сиду без `Math.random` внутри; если нет, фикстуру берём из `withSeed`, а не из интерфейса страницы.
- **Параллельная работа в `versum-dsp`.** Автор правит блоки там же; мои блоки идут отдельной веткой и тегом, чтобы не пересекаться.
