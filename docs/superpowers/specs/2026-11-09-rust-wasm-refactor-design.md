# Subversum: рефакторинг на Rust + WASM

Дата: 2026-11-09. Статус: черновик на ревью автора.

## 1. Цель и контекст

Сейчас всё приложение — один `index.html` на 3816 строк (замыкание 538–3808). Звук собран из нод Web Audio, события планируются через `setTimeout` (`atTime`), графика и звук делят состояние через замыкание (`lastBus`, `XV`, `ZH`, `PX`, хуки `SK.note` и `SK.pattern`), голоса дублируют друг друга, тестов и сборки нет.

Цели:
1. Отделить графику от звука. Единственная связь между ними — явный протокол.
2. Выделить в звуке переиспользуемые DSP-компоненты в отдельный публичный пакет.
3. Перенести звук на Rust, собрать в WASM и считать его в AudioWorklet.
4. Взять готовые решения из каталога DSP (`vault/dsp/Каталог DSP.md`), где они подходят.

Критерии успеха:
- Звук считается в Rust сэмпл за сэмплом, секвенсор точен до сэмпла (без `setTimeout`).
- Скин работает только от `Controls` и `Telemetry` и запускается без звука на синтетической телеметрии.
- DSP-блоки лежат в отдельном репозитории и подключаются как зависимость по тегу.
- Нативные тесты ловят NaN, аллокации, DC, алиасинг и выход за ±1 без браузера.

Решения автора (09.11):
- Звук выполняется в WASM внутри AudioWorklet.
- Звук можно переосмыслить: цель — сохранить характер мира, а не воспроизвести нынешнюю реализацию.
- Миграция вертикальным срезом, потом миры по одному.
- Rust и Vite собираются на Vercel (или в CI); в git лежат только исходники.
- DSP-пакет публичный, репозиторий `versum-dsp` на GitHub, подключается git-зависимостью по тегу.

Вне объёма: общий SDK с slow-tide, sreda-2, touch2decay (`versum-dsp` пишется так, чтобы это стало возможным, но совместное использование не проектируется); оверсэмплер 4× и SIMD; новые миры; нативное iOS-приложение.

## 2. Структура

```
subversum/
├─ crates/
│  ├─ engine/     миры, секвенсор, макросы, шина эффектов, протокол
│  └─ wasm/       тонкая обёртка extern "C", без логики
├─ web/
│  ├─ audio/      хост: загрузка wasm, AudioWorklet, порты команд и телеметрии
│  ├─ gfx/        скины (12 миров) и общий слой
│  ├─ input/      жесты: Pointer Events, свайп от края, веер, пинч, hold
│  └─ app/        сборка, PWA, HUD, шаринг, URL-параметры
├─ legacy/        нынешний index.html до переноса всех миров
└─ docs/superpowers/{specs,plans}
```

Репозиторий `versum-dsp` (github, публичный) подключается в `crates/engine/Cargo.toml`:
`versum-dsp = { git = "https://github.com/ai-slopes-hq/versum-dsp", tag = "v0.1.0" }`.
Владелец — `ai-slopes-hq` (там же `subversum`); локальная копия — `/Users/noise/code/versum-dsp`. Любое изменение API блока — новый тег. В разработке допускается локальный `[patch]` на рабочую копию, в git он не коммитится.

## 3. Контракт звук ↔ графика

Общего замыкания нет. Скин получает только `Controls` и `Telemetry` и не знает про `AudioContext`.

**Команды вниз (UI → engine).** Применяются в начале следующего блока:
- `Gesture{x, y, z, pinch}` — оси XY, время удержания Z и пинч;
- `SwitchWorld{id}`, `Seed{u32}`, `Tempo{bpm}`, `Hold{on}`, `Lock{on}`.

**Телеметрия вверх (engine → UI).** Публикуется раз на кадр (около 60 Гц):
- `Step{index, note, velocity}` — события секвенсора;
- `Peaks{l, r}` и энергия по 8 диапазонам;
- `Spectrum[32]` — только когда мир его запросил (overtones, scope).

**Транспорт.** Решение: базовый вариант — `postMessage` через порт AudioWorklet батчем раз в кадр. Он работает без заголовков COOP/COEP и не ломает Vercel Analytics. Кольцо на `SharedArrayBuffer` — необязательная оптимизация, вводится только если замер на устройстве покажет проблему с задержкой или нагрузкой, и только вместе с проверкой, что заголовки не ломают внешние скрипты.

## 4. Звук

**Контракт блока (`versum-dsp`).** Каждый блок: `new` (единственное место с аллокацией), `process(&mut self, ...)`, `reset()`; NaN-guard на выходе; никаких аллокаций и блокировок после `new`. Аудиоформат — f32, фазы и накопители — f64.

**Берём из каталога:** `Rng` (mulberry32; константы и деление совпадают с нынешним JS, поэтому поток случайных чисел для одного сида тот же; сами мелодии могут отличаться, если генератор переписан, и за это отвечает `?v=2`), `DcBlock{hz}`, `Knee`, `pan_eq`, `EdgeDetector`, `Ramp` и `OnePole`, `Delay` (внешний буфер, линейное и allpass-чтение), `Plate` (Dattorro), `Fdn`, пул голосов (oldest, quietest), `AD` и `Slope`, `Lpg` (вактрол-модель ST), `Quantizer`.

**Осцилляторы:** `Phasor` с отрицательным шагом; `Osc` (sine, tri, saw, pulse/PWM на minBLEP); `Wavetable` (64 кадра, кроссфейд, mip-таблицы по октавам); `Additive` (банк гармоник); `Fm2`; `Folder` (ADAA1 из S2, кривые tanh/asym/clip).

**Новые блоки для subversum:** `Grains`, `Lfo` (7 целей), `KarplusStrong`, `Acid303` (ladder-эрзац из S2), `Noise` (white, pink, brown), `StepClock` (16 шагов, swing, BPM 110–135, точность до сэмпла).

**Остаётся в `engine`:** реализации `World` (`on_gesture`, `on_step`, `render`), макросы `MAC` (XY, Z и пинч → параметры), шина dub как композиция блоков (фильтр, `Delay`, `Plate`, `Lfo`), тональность и общий пул MIDI C1..B2, лады по мирам, `handoff` между мирами, секвенсор и генератор мелодий.

**Строй.** Остаётся 12-TET (`440·2^((n−69)/12)`). Перенос в JI не входит в объём; обертонный ряд живёт внутри `Additive`.

## 5. Графика и ввод

Графика (DOM, SVG, canvas, CSS-переменные, 12 скинов) остаётся на JS и разносится по модулям `web/gfx`. Хуки `SK = {pattern, note, frame, idle}` становятся интерфейсом скина: `note(i, vel)` берётся из `Telemetry.Step`, `frame` — из rAF с `Peaks` и `Spectrum`. У скина нет доступа к `lastBus` и `ctx.currentTime`.

Ввод (`web/input`) остаётся на Pointer Events и отдаёт только `Gesture` и `SwitchWorld`. Состояния `XY`, `XV`, `FP` выносятся из замыкания в объект ввода; сглаживание `XV` остаётся на стороне графики, а звук получает сырые оси и сглаживает сам (`Ramp`).

URL-параметры: `?skin=`, `?seed=`, `?mod=0`, `?hud=1` сохраняются. `?v=1` остаётся за `legacy/`, для нового движка вводится `?v=2`, потому что звук и мелодии при том же сиде могут отличаться.

## 6. Сборка и деплой

- Rust собирается как `cargo build --release --target wasm32-unknown-unknown` без `wasm-bindgen` (интерфейс — `extern "C"` и линейная память). Модуль компилируется на главном потоке и передаётся в worklet через порт.
- Web-слои собирает Vite (TypeScript).
- Vercel: `installCommand` ставит Rust-toolchain и wasm-таргет (`rustup`), `buildCommand` собирает wasm, затем Vite; `outputDirectory` — `dist`. `legacy/` копируется в корень как есть, новое приложение лежит в `/next/`. Время холодной сборки замеряется на этапе 0; если оно неприемлемо, сборка переезжает в GitHub Actions с публикацией `dist` (решение принимается по замеру).
- `versum-dsp` публичный, поэтому Vercel забирает его без токена.
- PWA: `sw.js` обновляется под два корня; кэш `subversum-v3`.

## 7. Тесты и критерии готовности мира

Нативно (`cargo test`):
- «блоком = по сэмплу», побитово, для каждого блока и мира;
- счётчик аллокаций на `process` равен 0 (поток-локальный `GlobalAlloc`, как в ST и S2);
- метрики: DC после блока ≈ 0, пик ≤ 1, нет NaN, `alias_db` осцилляторов не хуже −70 дБ (порог принят как отправная точка: ST достигает −80), T60 реверберов в пределах ±15 %;
- нативный офлайн-рендер мира в WAV 24 бит для прослушивания без браузера.

Мир считается перенесённым, когда:
1. Нативный рендер патча проходит все проверки выше.
2. Скин запускается на синтетической телеметрии без звука.
3. Автор послушал мир на устройстве и принял характер (субъективный критерий).

## 9. Риски

- **CPU на телефоне.** Бюджет голосов и реверберов на мир фиксируется замером на устройстве, а не на глаз; превышение — повод упростить мир.
- **iOS Safari.** AudioWorklet и WASM проверяются на реальном устройстве на этапе 2, до переноса миров.
- **Время холодной сборки на Vercel.** Замер на этапе 0; запасной путь — GitHub Actions.
- **Стабильность API `versum-dsp`.** Зависимость закреплена тегом; изменения API идут новым тегом, переход `engine` на него — отдельным коммитом.
- **Субъективный критерий приёмки.** Звук миров принимает автор на слух; нативные метрики страхуют только от технических дефектов.
